# 通用编辑契约

所有任务先读取本文件。通用层只负责事实、来源、能力、隐私、CTA、品牌词、占位符、最小编辑和内容存在性判定，不规定任何语言的语序、敬语、标点、地区词、翻译腔或节奏。

## 输入账本

在写作或改稿前记录：

- 文字附着的 `surface`、受众、用户目标、当前状态和产品渠道；
- 候选信息的职责：动作、状态、结果、恢复、后果、导航/识别、信任/合规或内部诊断；
- 已知事实、数字、名称、日期、引语、条件和不确定性；
- 每项现实主张的来源，以及哪些内容只来自用户亲历；
- 产品实际具备的能力、权限、限制和恢复路径；
- 收集、使用、保存、删除和分享数据的真实行为；
- 读者应该执行的 CTA，以及产品是否真的支持该动作；
- 品牌词、产品名、术语和不可翻译词；
- 不可改写的 placeholder、变量、链接、标记和转义序列。

事实与能力账本是约束来源，不是公开文案的内容目录。内部实现、后端组成、团队流程和功能盘点只有在改变用户行动、预期、权限、隐私、费用、期限、不可逆后果或恢复路径时，才可能转成对外信息。

缺少的信息会改变事实、承诺或 CTA 时，只问一个聚焦问题。无法取得答案时，缩小主张、保留不确定性，或返回待作者决定，不用漂亮句子填补缺口。

## 事实与来源

- 现实内容只使用用户提供或可核验的事实。不得虚构检索、工具调用、客户、用户反馈、指标、引用、经历或现场细节。
- 来源只能证明它实际覆盖的范围。相关性不能替代因果，先后顺序不能自动写成因果。
- 数字、名称、日期、引语、否定、条件和确定程度在改写前后保持一致。
- 虚构内容可以创造设定、人物和事件，但不能把虚构材料包装成现实来源或用户亲历。

## 内容存在性门

在语言改写和组件措辞之前，为每条候选信息回答：

1. 这个受众在当前 `surface` 要完成什么动作、做什么决定或确认什么结果？
2. 省略这条信息会不会改变行动、预期、权限判断、隐私判断、恢复路径或必须履行的法律、安全、无障碍义务？
3. 这条信息是否属于当前表面的职责，并且有真实的下一步、结果或可取得的披露位置？
4. 页面、控件或辅助技术是否已经表达了同一件事？重复内容只增加噪声。

根据答案给候选信息一个处置：

- `keep`：当前信息有明确职责，原文可以保留；
- `rewrite`：职责成立，只需调整准确性、理解或目标语言自然度；
- `move`：信息有价值，但应放到帮助、权限、隐私、错误、空状态或其他更合适的表面；
- `remove`：没有用户职责、重复，或只是内部能力盘点。结构化资源只报告删除建议，不清空 value，也不擅自删除 key 或改变形状；
- `needs_product_decision`：缺少真实动作、状态、恢复路径或披露依据，改写会替产品决定能力或承诺。

`no_change` 表示 `keep` 且文字无需修改；`needs_author_decision` 继续用于事实或行动存在歧义的改稿。

候选信息处置与产品缺口可以同时成立。删除一句内部盘点不代表产品流程完整：如果候选暴露当前用户目标没有真实入口、CTA 或恢复路径，对文案返回 `remove`，同时对流程返回 `needs_product_decision`。如果页面的用户目标没有给出，只问一个聚焦问题，例如“这个页面是否应该让访客在这里完成任务，还是只提供阅读信息？”

### 能力边界的公开表达

默认不要把“没有后端、没有上传、没有第三方连接、没有入口”写成首页清单。先把内部事实映射为用户可观察的结果、受影响的选择和真实下一步：

- 页面只是介绍或指南时，删除内部能力盘点；
- 限制影响用户是否使用、授权、付费、上传、等待或执行不可逆动作时，在相应决定点说明用户需要知道的事实；
- 当前状态阻断任务时，用错误或空状态说明发生了什么并给出真实恢复或离开路径；
- 没有可用 CTA 或恢复动作时，对相关流程返回 `needs_product_decision`，不要用一段解释掩盖产品缺口；原候选文案仍可单独执行 `remove`。

例如，下面四条可以留在内部事实账本：

```text
没有处理服务；不接收文件；不连接外部系统；没有开始任务的入口。
```

它们在公开页面上的默认处置是 `remove`；如果用户会因此误解数据处理方式或产品范围，转写为已核实的用户后果并放到相应位置；如果确实存在选择或开始动作，只写真实动作，例如“选择一项内容后开始”。

## 能力、隐私与 CTA

- 能力账本约束公开承诺；公开文字只写产品当前能够完成的动作、用户可观察的结果和真实的恢复路径，不猜测权限、集成、可用性、速度或结果。
- 隐私文字只描述已确认的数据行为，不使用无法证明的“绝不”“完全安全”或同类保证。
- CTA 保持同一个行动、对象、条件和后果。不得为了简洁删掉期限、费用、不可逆结果或恢复限制。
- 跨语言版本可以长度和句式不同，但事实、能力边界、隐私承诺和 CTA 不能漂移。

## 品牌词与占位符

- 品牌词、产品名、批准术语和不可翻译词按输入账本原样保留。
- placeholder、变量名、ICU 参数、URL、markup 和转义不是普通文案。没有明确许可时，不翻译、不改名、不增删。
- 结构化 GUI 资源还要读取 `formats/gui-microcopy.md`，按源文件逐项核对 key、branch 和运行时结构。

## 最小编辑

1. 先通读完整输入，标出不可变信息和已经成立的文字。
2. 只修改影响准确性、理解、任务完成或目标语言自然度的部分；没有职责的候选信息执行 `remove` 或 `move`，不要用同义改写掩盖它的多余。
3. 保留作者已有的立场、正式程度、有效结构和有意义的不确定性，不把所有文字磨成同一种声口。
4. 原文已经自然且符合契约时返回 `no_change`；歧义会改变事实或行动时返回 `needs_author_decision`。
5. 不根据词表或分数声称作者使用了 AI，也不承诺规避任何检测器。

## 范围

语言自然度由一个 locale 档案负责，文字表面由一个 format 模块负责。本 Skill 只吸收 `kill-ai-slop` 中“具体、克制、先判断再改”的文本原则，不包含颜色、字体、布局、卡片、圆角、图标或动效规则。来源项目为 [yetone/kill-ai-slop](https://github.com/yetone/kill-ai-slop)，许可证为 [Apache-2.0](https://github.com/yetone/kill-ai-slop/blob/main/LICENSE)。
