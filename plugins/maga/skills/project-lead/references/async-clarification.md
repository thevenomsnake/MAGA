# Asynchronous Clarification

Use the host's asynchronous question tool when it is available and a short
preference or clarification can be answered while independent work continues.
Ask one focused question by default. If the tool is unavailable, ask in ordinary
conversation without claiming an asynchronous request was created.

Identify the work that depends on the answer. Continue only independent work;
steps whose correctness, product behavior, or authority depends on that answer
remain pending. A timeout, silence, or preselected option is not an answer or
authorization. Permission decisions still use the host's approval flow.

When an answer arrives, reconcile it with the current Ticket, completed facts,
and unfinished work. Apply it to unfinished work and explain any material effect
on completed work. Record a changed product decision before continuing affected
execution; do not treat a scope expansion as approval of unrelated work.

Use text-only question tools for text. Request files or screenshots through an
appropriate attachment surface, not through those tools. If the bridge cannot
handle a host input request, report that limitation; do not automatically answer
or approve it. This workflow adds no bridge input handler or custom question UI.

## Example

While preparing a report, ask which of two chart styles the user prefers. Gather
the already-authorized source data while the answer is pending, then use the
chosen style for the unfinished chart. A separate decision about publishing the
report stays pending; the style answer cannot authorize publication.
