# Codex 能力兼容与轻量工作流适配

## Problem Statement

产品所有者希望 MAGA 在 Codex 更新后继续可靠工作，并使用宿主已有的交互能力减少等待与重复配置。当前编排指导包含过期的置顶工具名称；Project Lead 尚未明确使用异步提问；桥接通过命令解析选择运行程序，缺少清楚的版本与能力说明；核心 Skill 的描述和入口过长。

这些问题可能造成工具调用失败、桌面与桥接能力不一致，以及本可继续推进的工作因普通澄清而停下。它们不意味着当前所有宿主都存在运行故障：本规格依据代码检查与官方文档，尚未进行真实宿主端到端复现。

## Solution

完成一次范围明确的兼容适配：

1. 编排使用当前宿主实际提供的置顶能力。
2. Project Lead 能在提出非阻塞问题后继续独立工作，并正确处理后来到达的答案。
3. 桥接能说明实际运行程序的版本及已确认、不可用或未知的能力。
4. 三个核心 Skill 保留准确的触发条件，把分支细节放到按需读取的参考资料。

保留 MAGA 的 Project Lead、Ticket、持久上下文和只读子代理边界。此次规格形成可实施需求，不安装宿主、不实现功能、不扩大既有权限。

## User Stories

1. 作为产品所有者，我希望 Project Lead 使用当前可用的置顶操作，让我能稳定找到项目入口。
2. 作为产品所有者，我希望宿主缺少置顶能力时仍可通过准确任务名称找到入口，并知道置顶尚未完成。
3. 作为产品所有者，我希望普通偏好问题不会阻塞不依赖答案的工作。
4. 作为产品所有者，我希望稍后提交的答案能影响尚未完成的工作，而不是被丢弃或当成另一项无关任务。
5. 作为产品所有者，我希望影响事实、产品行为或权限的问题保持待决，直到我作出决定。
6. 作为产品所有者，我希望未回答或等待超时不会被视为同意、授权或已选定默认选项。
7. 作为产品所有者，我希望旧宿主无法异步提问时仍能收到简短、清楚的问题。
8. 作为维护者，我希望知道桥接实际调用的运行程序及版本，能够识别桌面与命令行的差异。
9. 作为维护者，我希望版本获取失败显示为未知并说明原因，而不是误报为不支持所有能力。
10. 作为维护者，我希望能力判断有实际工具、协议或元数据依据，不因版本较新就推断全部功能可用。
11. 作为产品所有者，我希望普通任务只加载相关 Skill 指导，保持交流和执行简洁。
12. 作为维护者，我希望 Skill 精简后仍保留本地文件触发范围、任务创建授权和资源保护等明确边界。
13. 作为产品所有者，我希望已保存的模型选择和现有任务保持原有配置。
14. 作为维护者，我希望公开项目状态只保存可复用结论，不包含本机路径、账号或运行时任务标识。

## Implementation Decisions

### 1. 宿主工具兼容

- 在任务编排入口修正旧的 `set_thread_pinned` 引用。当前桌面工具通过 `move_thread_to_sidebar_section`、目标分区 `pinned` 完成置顶。
- 操作前以当前会话实际工具定义为准；工具名称只是已知映射，不是跨版本保证。
- 不可用时保留已创建的任务，返回准确标题与未完成的置顶状态；不重复创建任务，不宣称置顶成功。
- 此处修改的是桌面工具指导。桥接现有的任务元数据协议属于另一接口，不因桌面工具改名而机械替换。

### 2. 原生异步提问

- Project Lead 在宿主提供异步提问能力时，用其提出简短、独立、可回答的问题；普通问题优先只问一个。
- 只把不会改变当前独立工作正确性的偏好或澄清作为非阻塞问题。依赖答案的执行保持待决。
- 到达的新答案先与当前 Ticket、已完成事实和未完成工作核对，再继续执行。明显扩大范围的答案形成新决定，不静默扩张原 Ticket。
- 未回复、超时、预选项均不构成授权。权限审批继续使用宿主原有审批流程。
- 工具不支持附件时，不通过它请求文件或截图。能力不可用时使用普通对话，不模拟工具成功。
- 这轮不实现自定义问答 UI、消息队列或桥接审批处理器。桥接无法处理的宿主问题继续明确返回限制；不得为消除错误而自动回答或批准请求。

### 3. 运行程序与能力识别

- 在现有 CodexBridge 接口上提供小型只读诊断结果，复用已有命令选择、初始化和模型目录能力，不另建服务。
- 诊断区分运行程序版本与功能可用性。版本读取来自实际配置的执行命令；桌面应用版本不替代此值。
- 能力至少区分已确认可用、已确认不可用、未知，并附简短依据或失败原因。未知不得伪装为成功或普遍不支持。
- 以官方 0.154.0 的能力变化作为本轮兼容参考，不将其直接设为所有 MAGA 功能的强制最低版本。
- 原生子代理仍遵守既有接受记录中的只读、数量限制和能力判断；本轮不放宽白名单、不新增子代理协议。
- 诊断失败不修改全局配置、不自动安装、不静默切换到另一个运行程序。需要具体能力但无法确认时，返回该操作的限制和现有回退路径。
- 机器相关细节仅保留于本次运行结果；公开规格、Ticket 和日志示例使用通用内容。

### 4. 核心 Skill 精简

- 覆盖 Project Lead、Orchestrate Tickets、Humanization 三个入口。
- description 只说明职责、触发条件与必要的排除边界；执行步骤、工具细节和长示例放入正文或条件明确的参考文件。
- 主入口保留共同步骤与完成条件，多分支规则通过明确指针按需加载。不增加新的注册 Skill。
- 保留 Humanization 的本地文件自动触发、聊天输出排除、旧命令兼容和完整审计显式触发规则。
- 保留 Ticket 授权、子代理与独立任务的区别、已有任务复用、来源保护和一次风险匹配验证。
- 宿主对创建独立任务的明确要求优先于 MAGA 的一般编排建议；项目 Autonomy Policy 不覆盖宿主限制。
- 以消除重复与改善触发准确性为验收依据，不设置任意字符数、文件行数或 token 节省指标。

### 5. 兼容与交付

- 不改变职责模型预设、用户已保存配置、Goal 状态、任务并发数、沙箱权限或发布授权。
- 沿用现有项目记忆格式与已接受设计记录。新增诊断结果只扩展接口，不迁移现有项目状态。
- 实现后提交并合入 main，推送 main，清理已合并工作分支；不自动发布 npm、网站或 GitHub Release。

## Testing Decisions

### 现有验证接口

- 运行程序与能力识别复用 CodexBridge 的现有可替换命令和协议测试接口。验证调用者看到的结果与回退行为，不断言私有函数结构。
- Skill 与置顶指导复用现有打包/路由检查。只更新受实际改动影响的断言，不建立全文快照或强制字数测试。
- 原生异步提问属于宿主交互规则；用一个有代表性的行为示例检查指导是否允许继续独立工作、保留依赖工作并接纳答案，不搭建浏览器矩阵。

### 验收边界

- 置顶操作只在宿主返回成功后报告完成；缺少能力不产生重复任务。
- 问题待答时独立工作可继续；需要答案或授权的工作保持待决。
- 版本来自配置的执行命令；不可读取、功能不可用与功能未知有可区分结果。
- 三个 Skill 的新入口能找到相关参考，原有触发与授权边界仍可检索。
- 验证报告区分真实宿主观察与替身协议结果，不把后者称为端到端兼容通过。

先实现最短可运行切片，再对本次改变的事实做一次直接相关的测试或 smoke。复用已有通过且未受影响的结果；不采用 TDD、双轴 review、全量回归、新测试框架或多阶段门禁。若实际实现需要更改权限处理、并发控制或其他高风险行为，先缩小范围；仍需扩大时说明具体风险与最小额外验证，等待产品所有者确认。

## Out of Scope

- 更新或安装 Codex 桌面应用、CLI、全局 Skill 或插件缓存。
- Astra 职责预设、自动更换模型、自动升高 reasoning effort。
- 原生 worktree 接入、后台服务、daemon、自动化调度或 heartbeat。
- 桥接异步问答协议的完整实现、自定义审批系统与自动授权。
- 扩展子代理写入能力、并发数量或独立任务创建权限。
- Pets、Appshots、语音及新增可视化界面。
- Humanization 4.1 的强制 manifest、逐句回执与全文件扫描机制。
- npm、网站、Cloudflare 或 GitHub Release 发布。

## Further Notes

- 跟踪方式：沿用仓库文件式规格目录，状态 `ready-for-agent` 表示可进入后续拆分和实现准备；不表示所有外部操作或风险边界已获批准。
- 产品所有者已确认复用现有桥接测试接口与 Skill 打包检查，每个实际改动只做一次直接相关验证，不新增框架或全量回归。
- 本规格不替代已有原生子代理设计决定，也不把官方新增能力直接解释成 MAGA 的新增权限。
- 官方能力信息以 2026-09-15 检查结果为基础；实现时只针对实际依赖的接口确认宿主可用性。
